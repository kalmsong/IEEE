# GENIE.AI 및 도구 구조

## 개념 구분

- **LLM**: 문장 이해·요약·답변을 생성하는 언어모델. Qwen 등 오픈소스 모델을 선택해 구동 가능.
- **GENIE.AI**: 정부·공공기관이 자체 데이터와 언어모델을 기반으로 문서 검색 및 질의응답(RAG) 등을 운영하기 위한 오픈소스 플랫폼. **도시 GIS나 건물 에너지 계산을 자체 완성 제공하는 프로그램은 아님.**
- **전문 도구**: 도시 행정용 GIS 처리, 자료 추출, 에너지 수치 계산, 검증, 보고서 제작 같은 과제별 기능.
- **웹 UI**: 스코페의 녹지대장 담당자나 리브네의 건물 소유자가 실제로 사용하는 업무 화면.
- **ADK**: 필요한 경우 다단계 에이전트 실행을 돕는 별도 프레임워크. GENIE와 역할이 다르며, 병행을 제안할 수 있지만 연결·인증·운영 복잡성은 검증 필요.

## 제안용 구성(검증 전)

```text
[스코페/리브네 업무 웹 UI]
       ↕
[서버 API / 사용자 권한 / 감사로그]
       ↕
[GENIE: RAG / 문서 색인 / 모델 실행]
       ↕
[시범 도시 전문 도구: GIS 또는 에너지 계산]
       ↕
[시범 도시 데이터 / 담당자 검토 / 승인·출력]
```

에이전트 작업 분배가 유의미할 때만 ADK를 별도 기능으로 붙인다. 현재 F.AIR를 GENIE로 전면 교체하지 않는다. 기존 운영 데이터와 공모전용 공개 데이터를 분리한다.

## 1차와 본 개발의 차이

- **1차 서술형 제안**: GENIE를 어디에, 왜 사용할지 아키텍처로 설명.
- **1차 Zindi 시험**: GENIE 사용 요구 없음. 3B 이하 공개 생성모델과 허용된 도구로 범용 QA 엔진 작성.
- **선정 후 시제품 단계**: GENIE 기반으로 실제 도시 업무 기능 구현·실증.

## 검증할 쟁점

1. GENIE API·검색 엔진·권한 모델과 기존 ADK 도구의 연결 범위.
2. 사용하는 공개 LLM의 로컬 실행 환경(GPU/메모리/언어 지원).
3. 스코페 마케도니아어 추출·좌표 매칭 또는 리브네 공식 수치계산의 신뢰성.
4. 공개 라이선스 범위와 기존 AIRTECT 자산 분리.
